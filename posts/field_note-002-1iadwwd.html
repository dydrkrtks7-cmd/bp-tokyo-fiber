구글 검색 엔진 크롤러의 효율적인 리소스 할당을 위한 응답 헤더 최적화

구글의 검색 로봇이 당신의 사이트를 방문할 때, 단순히 페이지 내용을 긁어가는 것이라고 생각한다면 오산이다. 크롤러는 대역폭을 낭비하지 않도록 설계된 정교한 알고리즘의 집합체다. 서버 응답 헤더에서 불필요한 데이터를 걷어내는 것만으로도 초당 요청 처리량을 비약적으로 높일 수 있다. 많은 관리자가 웹 페이지 용량 최적화에는 집착하면서, 정작 서버가 건네는 응답 헤더에 담긴 비효율적인 쿠키 데이터나 중복된 서버 식별자에는 무심한 경우가 많다. 이 작은 데이터 쪼가리들이 수만 번의 요청에서 합쳐지면 결과적으로 크롤 가속화를 방해하는 병목 현상을 유발한다.

응답 헤더 내의 세션 식별자나 트래킹을 위한 매개변수를 제거하는 것은 필수다. 크롤러는 사람처럼 쿠키를 통해 세션을 유지할 필요가 없기 때문이다. 서버가 매번 정적인 페이지를 응답할 때마다 불필요한 쿠키 값을 설정하려 들면, 구글 봇은 이 정보를 처리하기 위해 미세하지만 명확한 연산 자원을 소모한다. 이런 자잘한 부하가 누적되면 구글이 당신의 사이트에 할당한 크롤 예산은 바닥나고, 결과적으로 업데이트된 정보가 색인되는 속도가 늦어질 수밖에 없다. 서버 설정 파일에서 특정 봇이 접근할 때만 헤더를 정제하는 조건문을 넣는 것이 귀찮다면, 애초에 정적 자산에서 불필요한 헤더를 완전히 배제하는 것이 상책이다.

압축 방식인 지팁이나 브로틀리를 서버 헤더에서 적절히 협상하는 과정도 중요하다. 단순히 압축만 한다고 끝나는 게 아니다. 브라우저와 봇이 서버와 통신할 때 어떤 압축 방식을 우선할지 결정하는 협상 헤더가 지나치게 길어지거나 복잡하게 얽혀 있다면, 서버는 매 요청마다 이를 해석하느라 시간을 허비하게 된다. 봇은 주로 압축된 데이터를 선호하지만, 서버가 이를 전달하기 전에 어떤 알고리즘으로 데이터를 뱉어낼지 결정하는 과정에서 발생하는 찰나의 지연이 크롤링 속도를 결정짓는다. 최신 프로토콜을 사용하라는 말은 너무 흔해서 지겹겠지만, 여기서 말하는 핵심은 단순히 최신 방식을 도입하는 게 아니라 서버 설정에서 봇에게 우선순위를 부여하는 것이다.

서버가 봇의 요청을 처리하는 논리 구조를 단순화할 필요가 있다. 조건부 요청에 대한 응답을 다룰 때 봇이 보낸 이태그 값을 비교하는 과정에서 서버가 디스크를 계속 긁고 있다면 이는 하드웨어의 문제가 아니라 데이터베이스와 서버 간의 비효율적인 통신 방식 때문이다. 봇은 변경된 사항이 없으면 삼백사 응답을 원하는데, 서버가 매번 전체 파일을 다시 읽어 이태그를 계산하고 있다면 이는 전력과 대역폭의 낭비다. 이런 식으로는 아무리 비싼 광회선을 들여와도 크롤 가속화는 요원하다. 데이터 처리 로직을 효율적으로 짜는 것, 그것이 구글 봇에게 당신의 사이트가 매력적으로 보이는 유일한 방법이다.
